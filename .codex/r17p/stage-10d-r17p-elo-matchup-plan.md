# R17P team-strength / matchup plan

The reusable underlying producer is safe to reuse; the final coach fantasy projection is not. `team_win_model.EloTracker` uses 1500 initial ratings, expected probability `1/(1+10^((R_opp-R_team)/400))`, K=32 in the coach/game lookup, and sequential atomic game updates `R += K*(actual-expected)`. It has no home/side term or explicit streak term; opponent strength enters through the opponent rating. `build_pregame_elo_lookup` records probability before each update. `conditional_coach_projection` separately uses win/loss team-score histories, 180-day exponential decay, prior strength 3, and combines them with the probability. That final output must never be a player feature.

There is also an OATS series tracker (K=48, split carryover 0.75) but it belongs to an excluded candidate lineage; R17B must choose one explicit new player-team producer, not mix the two by accident. The preferred starting producer is a dedicated canonical-PIT sequential Elo replay with versioned initialization, scale, K, split-reset/carryover, deterministic same-timestamp ordering, and per-(team,scheduled opponent) pre-lock rating/probability records. Schedule aggregation is an arithmetic average of per-scheduled-series matchup terms with equal pre-lock series weights unless the official schedule supplies a pre-lock fixed weighting; it is not realized-game weighted.

Candidate term: `delta_matchup_player = beta * aggregate(delta_team_matchup) * S30_share`, with `delta_team_matchup` formed from centered pre-lock rating difference / calibrated win probability. Fit beta and centering only on chronological development rows, preserve `elo_self`, `elo_opponent`, `p_win`, aggregate rule, `delta_matchup_team`, and player allocation columns. Unknown opponent/rating returns neutral zero delta and a reason code. The R17B test must demonstrate incremental value beyond frozen FE, cutoff replay parity, two-opponent averaging, no schedule-volume inflation, and future inference without labels.
